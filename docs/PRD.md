# NEXT CUP 요구사항 / v08

## 문제와 가설

좋아했던 음료를 현재 찾을 수 없을 때, 같은 맛이 아니어도 남기고 싶은 특징을 확인하면 다음 선택의 후보를 비교할 수 있다는 가설입니다.
본인 경험 1건으로 문제를 정했고 공개 자료와 가상 입력으로 구현을 시험했습니다. 같은 불편을 겪는 고객이 얼마나 있는지, 서비스가 실제로 도움이 되는지는 아직 확인하지 못했습니다.

## 핵심 흐름과 완료 조건

| 단계 | 구현 | 완료 기준 |
|---|---|---|
| 기억 입력 | 자유 문장, Gemini 전송 동의, 직접 선택 | AI 실패에도 입력 보존 |
| 취향 확인 | 선호/비선호/쌀 필수, 추가 필수 특징 수정 | 모순된 조건은 차단, 미확인 쌀 조건은 선택 요청 |
| 후보 비교 | 등록된 5종, 현재 근거 범위 검사 | 필수 조건 위반/비선호 포함 후보 제외 |
| 추천 보류 | 맞는 후보가 없으면 보류 안내 | 목록 한계를 전체 시장 부재로 말하지 않음 |
| 남은 요구 | 확인 조건과 자유 문장을 기기 안에 저장 | 가입/공개 전송 없음, 새로고침 뒤 유지 |

## AI의 역할

자유로운 기억을 등록된 특징으로 정리합니다. 최종 후보를 직접 창작하지 않습니다.
출력 형식과 등록 태그, 사용자 발언의 인용 여부를 검사합니다. 의미의 정확성은 이 검사만으로 보장할 수 없으므로 사용자가 수정합니다.
추가 필수 특징은 사용자가 직접 정합니다. AI 입력이 직접 고르는 방식보다 편한지는 다음 시험에서 확인할 계획입니다.

## 데이터와 운영 범위

추천 5종: 딸기 딜라이트 요거트 블렌디드, 망고 패션 프루트 블렌디드, 초콜릿 크림 칩 프라푸치노, 카페 라떼, 바닐라 크림 콜드 브루.
공식 설명과 설계 해석을 tagBasis로 구분합니다. 실시간 지점 재고나 시음 점수가 아닙니다.
이력 조사 6종과 추천 5종은 서로 다른 범위입니다. 과거 지역 확대 이력을 현재 판매처로 사용하지 않습니다.
서버 12초 제한, 수동 전환, 늦게 도착한 응답 적용 차단, 하루 40회 한도를 둡니다.
출처 조회 실패는 미확인으로 남기고 단종으로 변경하지 않습니다.
정기 점검은 일정과 실제 완료 기록을 구분합니다. 이번 공식 목록 수동 확인은 예약 실행 실적이 아닙니다.

## 제외

회원가입, 공개 커뮤니티/투표, 실제 주문, 스타벅스 제출, 제조 레시피 자동 생성, 매출/수요 예측.
이전 서버 모듈은 보존하지만 고객 화면에서 사용하지 않습니다.
