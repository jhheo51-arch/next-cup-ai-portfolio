좋아했던 음료의 맛과 질감을 바탕으로 지금 마실 후보를 비교합니다. 필수 조건에 맞는 후보가 없으면 추천을 보류하고, 찾지 못한 특징을 기록합니다.
스타벅스 AI 기획/개발 지원용 개인 프로젝트입니다. 스타벅스 공식 서비스는 아닙니다.

## 시작한 이유

저는 이천 햅쌀 크림 프라푸치노의 구수한 맛과 갈린 질감, 과자 같은 토핑을 좋아했습니다.
이후 딸기 딜라이트 요거트 블렌디드를 고른 데에는 시원하게 갈린 음료를 좋아했고, 당시 추천을 받았다는 이유가 있었습니다.
이 경험에서 이번에도 원하는 특징을 먼저 확인하는 방식을 생각했습니다.

기억 입력 → 취향 확인 → 대안 또는 추천 보류 → 남은 요구 기록

| 직접 확인한 조건 | 결과 |
|---|---|
| 요거트 풍미 필수, 갈린 질감 선호, 초콜릿 제외, 쌀 필수 아님 | 딸기 딜라이트 요거트 블렌디드 |
| 갈린 질감 필수, 초콜릿 제외, 쌀 필수 아님 | 딸기 요거트와 망고 패션 프루트 |
| 쌀 풍미 필수 | 등록한 5종에서는 추천 보류 |

Gemini가 문장에서 취향을 정리하면 사용자가 수정합니다. 최종 후보는 코드가 필수 조건과 피하고 싶은 특징을 검사해 고릅니다.
같은 맛을 재현하거나 매장 재고를 확인하는 서비스는 아닙니다. 표의 조건은 시험용이며 제 실제 취향을 모두 뜻하지는 않습니다.

## 확인한 결과

- 자동 검사 123개, 가상 AI 응답을 사용한 화면 검사 14개 통과.
- 기존 연결 시험의 실제 Gemini 호출 4회: 시험용 입력 3개를 실행하고, 검사 절차 오류가 있던 R03을 한 번 더 실행했습니다.
- 최초 실패 기록도 남겼습니다. 자세한 결과는 [검증 기록](docs/VALIDATION.md)에 있습니다.
- 외부 이용자 시험은 아직 하지 않았습니다. 실제로 음료를 고르기 쉬워지는지는 더 확인해야 합니다.

3종 목록의 해석 시험 24회와 5종 목록의 연결 시험 4회는 사용한 목록과 AI 지시문이 달라 분리했습니다.

어려운 표현 16개의 평가 기준을 작성했으나 실제 해석 평가는 연결 실패로 미완료입니다. 기본 모델의 503 혼잡 응답을 확인했고, 대체 모델 시험도 실패해 결과를 따로 남겼습니다. 분리 평가 문장은 실행하지 않았습니다.
가상 장애/복구 시험에서는 AI 확인 질문이 화면에 빠지는 문제를 찾아 수정했습니다. 같은 검사에서 7/8개에서 8/8개로 바뀌었으며 고객 효과 수치가 아닙니다.

기존 실제 AI 응답을 화면에 다시 적용해 직접 선택과 비교했습니다. 같은 목표 조건까지 바꾼 값은 5→1, 2→0, 6→6개였습니다. 입력과 읽기, 대기 시간은 제외했으므로 사용자 편의나 시간 절감으로 해석하지 않습니다.

PDF, Excel과 이 설명은 2026-10-08 기준으로 맞췄습니다. PDF 10쪽과 Excel의 ‘판단과 복구’ 시트에 입력 비교를, ‘해석 심층시험’ 시트에 후속 연결 실패를 구분해 담았습니다. 파일 확인값은 [제출 기록](submission/RELEASE.json)에 있습니다.

## 실행

Node.js 24 이상에서 저장소의 최상위 폴더를 열고 실행합니다.

```bash
npm test
npm start
```

화면 검사도 실행하려면 다음 명령을 사용합니다. GitHub 자동 검사에서는 아래 14개 화면 검사와 위 123개 코드 검사를 모두 실행합니다. 화면 검사는 가상 AI 응답과 임시 저장소를 사용하며 실제 AI 요청은 보내지 않습니다.

```bash
npm ci
npx playwright install chromium
npm run test:browser
```

접속 주소: http://127.0.0.1:4322

Gemini를 사용하려면 최상위 .env.example을 .env로 복사하고 본인 API 키를 넣습니다.
키가 없어도 ‘AI 없이 직접 선택할래요’로 비교할 수 있습니다. 키와 기기 내 기록은 GitHub에 올리지 않습니다.
자세한 방법은 [실행 안내](docs/HANDOFF.md)에 있습니다.

## 구현 범위와 본인의 역할

남은 요구는 본인 브라우저에만 저장합니다. 공개 게시, 실제 주문, 스타벅스 제출, 레시피 생성은 구현하지 않았습니다.
매출/수요 예측과 전사 데이터 전략도 이 프로젝트에서 다루지 않았습니다.

저는 문제와 기능 범위를 정하고 결과를 검토했습니다. 조사 보조와 코드 작성/시험에는 Codex를 사용했고, 서비스의 취향 해석에는 Gemini를 연결했습니다.
